# Hi, I'm Hritik

I'm interested in AI products and like building things in that space.

Most of the repos here are small, self-contained projects I built to understand how LLM systems work — plus a few tools I use day to day. Everything is meant to be easy to clone and run.

### Learning the stack

From-scratch builds of the pieces behind a language model. Written to learn how things work, not for production use.

- [mosaic](https://github.com/Hritikd/mosaic) — a byte-pair-encoding tokenizer you can train on your own text · [demo](https://hritikd.github.io/mosaic/)
- [nabla](https://github.com/Hritikd/nabla) — a small reverse-mode autograd engine with a visualizer · [demo](https://hritikd.github.io/nabla/)
- [loom](https://github.com/Hritikd/loom) — a small GPT written in NumPy, trained on Shakespeare · [demo](https://hritikd.github.io/loom/)
- [warren](https://github.com/Hritikd/warren) — HNSW nearest-neighbor search, the algorithm behind vector databases · [demo](https://hritikd.github.io/warren/)

### Tools and experiments

Practical pieces around LLM apps. Most run without any API keys.

- [tinycoder](https://github.com/Hritikd/tinycoder) — a minimal coding agent in ~570 lines of Python
- [stencil](https://github.com/Hritikd/stencil) — constrained decoding: guide generation with a JSON Schema · [demo](https://hritikd.github.io/stencil/)
- [winnow](https://github.com/Hritikd/winnow) — packs the most relevant context into a token budget for RAG · [demo](https://hritikd.github.io/winnow/)
- [mend](https://github.com/Hritikd/mend) — repairs malformed JSON from LLM output · [playground](https://hritikd.github.io/mend/)
- [semcache](https://github.com/Hritikd/semcache) — a semantic cache for LLM calls
- [introspect-mcp](https://github.com/Hritikd/introspect-mcp) — MCP server that serves real signatures from your installed packages
- [deja](https://github.com/Hritikd/deja) — local search over your Cursor/Claude agent transcripts
